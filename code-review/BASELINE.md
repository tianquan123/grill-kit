# 坏味道基线（兜底）

**只在仓库没有任何成文规范时读这份文件。** 仓库有成文规范时不需要它；即使作为补充，**仓库规范永远赢**——仓库认可而基线会挑刺的地方，压掉那个坏味道。

每条读作*它是什么* → *怎么修*；拿它去比对 diff：

- **神秘命名（Mysterious Name）**：函数、变量或类型的名字不能揭示它做什么或装什么。→ 改名；如果想不出诚实的名字，说明设计本身含糊。
- **重复代码（Duplicated Code）**：同一段逻辑形状在本次改动的多个 hunk 或多个文件里出现。→ 抽出共享形状，两处都调它。
- **依恋情结（Feature Envy）**：某个方法访问别的对象的数据比访问自己的还多。→ 把这个方法搬到它依恋的数据上去。
- **数据泥团（Data Clumps）**：同几个字段或参数总是结伴出行（一个想要诞生却还没诞生的类型）。→ 把它们打成一个类型，传那个。
- **基本类型偏执（Primitive Obsession）**：用基本类型或字符串顶替一个配得上自有类型的领域概念。→ 给这个概念一个小类型。
- **重复的 switch（Repeated Switches）**：对同一类型的同一个 switch/if 级联在改动里反复出现。→ 换成多态，或换成一个两处共用的映射表。
- **霰弹式修改（Shotgun Surgery）**：一次逻辑改动逼你在 diff 的许多文件里零散地改。→ 把一起变化的东西聚到一个模块里。
- **发散式变化（Divergent Change）**：同一个文件或模块因为几个不相关的原因被改。→ 拆开，让每个模块只因一个原因而变。
- **夸夸其谈通用性（Speculative Generality）**：为 spec 并不存在的需求添加抽象、参数或钩子。→ 删掉；内联回去，直到真实需求出现。
- **过长的消息链（Message Chains）**：调用方不该依赖的长链 `a.b().c().d()` 导航。→ 把这段走链藏到第一个对象的一个方法后面。
- **中间人（Middle Man）**：一个类或函数大部分只是往下转发。→ 砍掉它，直接调真正的目标。
- **被拒绝的遗赠（Refused Bequest）**：子类或实现者忽略或覆盖了它继承来的大半东西。→ 放弃继承，改用组合。

**每个坏味道都是带标签的启发式**（「疑似 Feature Envy」），绝不是硬性违规。工具已经能管的一律跳过。
