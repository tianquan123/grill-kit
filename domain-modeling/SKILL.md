# 领域建模

在设计过程中主动构建并打磨项目的领域模型。这是一门*主动的*功夫：挑战用词、虚构边界场景，并在术语、不变量和决策一成形时就写下来。（仅仅为了查词汇而*读* `CONTEXT.md` 不算这个技能 —— 那是任何技能都能做的一行习惯。这个技能用于**改动**模型，而不是只消费它。）

局部档里如果没有新术语、没有新不变量、也没有难逆的决策，就不用走这个技能——它不是流程里必须打卡的一站。

## 文件结构

多数仓库只有一个上下文：

```
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-event-sourced-orders.md
│       └── 0002-postgres-for-write-model.md
└── src/
```

若根目录存在 `CONTEXT-MAP.md`，说明仓库有多个上下文。该地图指向每一个上下文所在的位置：

```
/
├── CONTEXT-MAP.md
├── docs/
│   └── adr/                          ← 系统级决策
├── src/
│   ├── ordering/
│   │   ├── CONTEXT.md
│   │   └── docs/adr/                 ← 该上下文专属决策
│   └── billing/
│       ├── CONTEXT.md
│       └── docs/adr/
```

**按需创建文件**：只在真有东西可写时才建。没有 `CONTEXT.md` 就在第一个术语确定时创建；没有 `docs/adr/` 就在第一条 ADR 需要时创建。

## 三个文件各放什么

| 文件 | 放什么 | 判据 |
|---|---|---|
| `CONTEXT.md` | **术语**（`## 术语`）+ **领域不变量**（`## 不变量`） | 是"一个词"或"永远成立的领域规则"吗？ |
| `docs/adr/NNNN-*.md` | 难逆、不写就费解、真做过取舍的**决策** | 是"我们为什么这么选"吗？ |
| `docs/specs/<slug>.md`（由 `to-spec` 写） | **意图**、备选方案与取舍、决策、验收清单、范围外 | 是"这次要做什么、为什么"吗？ |
| `docs/plans/<slug>.md`（由 `to-plan` 写） | **任务**、状态、每任务的验证项、裁决记录 | 是"按什么顺序做、做到哪了"吗？ |

`CONTEXT.md` 只收上表第一行那两类，其余一概不进。

## 会话过程中

### 用术语表来挑战

当用户使用的词与 `CONTEXT.md` 中已有的语言冲突时，立刻指出来。"你的术语表把 'cancellation' 定义为 X，但你现在似乎指的是 Y。到底是哪个？"

### 打磨模糊的语言

当用户使用含糊或一词多义的词时，提出一个精确的规范术语。"你说的 'account'：是指 Customer 还是 User？这是两个不同的东西。"

### 讨论具体场景

讨论领域关系时，用具体场景去压测它。虚构能戳中边界情况的场景，逼用户把概念之间的边界说清楚。

### 把不变量逼出来

具体场景同样是挖掘**不变量**的主要手段：反复问"如果发生 X 会怎样？"，直到撞上一条永远不能违反的规则。不变量是**与实现无关、永远成立**的领域事实（"订单金额永远为正"），不是"这次要不要做某件事"。

### 与代码交叉验证

当用户陈述某件事怎么运作时，检查代码是否同意。发现矛盾就摆出来："你的代码取消的是整张 Order，但你刚说可以部分取消。哪个才是对的？"

### 就地更新 CONTEXT.md

术语或不变量一确定，就当场写进 `CONTEXT.md`。不要攒着批量写：确定一条记一条。格式见 [CONTEXT-FORMAT.md](./CONTEXT-FORMAT.md)。

`CONTEXT.md` 里只有**术语**和**不变量**，此外什么都没有：不含实现细节，不是规格说明，不是草稿纸，也不是实现决策的仓库。意图去 `docs/specs/`，执行计划去 `docs/plans/`，决策去 ADR。

### 克制地提议 ADR

只有以下三条**同时**成立时，才提议创建 ADR：

1. **难以逆转**：以后改主意代价可观
2. **没有背景会让人意外**：未来的读者会想"他们当时为什么这么做？"
3. **是真实取舍的结果**：确实存在过别的选项，你基于特定理由选了其中一个

三条缺任意一条就跳过。技术约束（性能指标、合规限制、选型锁定）属于 ADR，**不属于** `CONTEXT.md`。格式见 [ADR-FORMAT.md](./ADR-FORMAT.md)。

## 这次建模算做完了吗

判据是穷尽的：**这次谈定的每一条术语与不变量，都已经写进 `CONTEXT.md`；每一条同时满足上面三条的决策，都已经落成 ADR。** 只存在于对话里的，不算。
