# 实施：逐任务推进

在一份**已经签过字**的实施计划上作业。开工前先读计划里记下的设计文档路径；计划没写，就停下来让 `to-plan` 补上，不要自己猜设计意图。

<HARD-GATE>
没有计划就停下来：调用 `to-plan` 生成一份并拿到签字。不许「边做边想」。
</HARD-GATE>

三条硬规矩：

1. **当前分支、当前会话。** 不新建 worktree，不另开会话；实现工作不派子代理替你做。`code-review` 的两个评审子代理不在此列。
2. **不提交。** 提交是用户自己的事。你的「任务完成」判据里**不含提交**。
3. **进度记在计划文件里。**

## 配套技能：由 `use-grill` 预载

写代码用的 `ponytail`（最小实现）和 `spring-boot-conventions`（后端放置位置）由 `use-grill` 按「写代码前的加载」预载；本技能不重复判定。

- **被直接调用、发现没加载**：回到 `use-grill` 的「写代码前的加载」一节按判据补载。
- **加载不到**：在计划文件里记一行原因，按最小实现底线和任务里写明的约束做，收尾报告时说明——不要默默假装按它做过。
- **边界不变**：`ponytail` 不压缩计划范围、`tdd` / `constraints` / 验证项，也不压缩收尾报告；`spring-boot-conventions` 的放置位置结论记进计划文件。

## 循环

对计划里的每个任务，按顺序：

1. **读任务**：交付物、要碰的位置、覆盖哪些验收、验证什么。
2. **先记录开始或恢复现场**：任务是 `[ ]` 就立即标成 `[~]`；任务已经是 `[~]`，说明上次中断了，先核对现有 diff 和任务记录，再从断点继续，不要从头重做。
3. **动之前先确认位置对得上**——碰后端代码时按 `spring-boot-conventions` 走一遍放置位置判断（进入实现前应已加载）；改名了、挪走了、还要多碰一处，就把任务里的位置就地更新。
4. **按 `tdd` 做**——仓库没有测试基建时走哪条路，它自己写了。写之前先过 `ponytail` 的判断顺序，选能跑通的最小实现。
5. **跑这个任务的验证项**。跑之前先过 `constraints` 的五个放松动作——**不许改测试、改阈值、加抑制注释让它过**。跑不动（环境不允许）就把原因记下来，交给 `verification` 在收尾时显式标注，**不许当成通过**。
6. **记录结果**：补一行「实际碰了哪儿、验证是怎么做的」；验证支持任务完成时才把 `[~]` 标成 `[x]`。
7. **下一个任务。**

`[~]` 是任务开始前的写前记录，`[x]` 是验证后的完成记录；两次都要当场写进计划文件，不要攒到最后一起更新。

## 卡住的时候

**修复循环上限 3 轮。** 同一个任务连续三轮验证不过，停下来报告：现在什么状态、试过什么、你判断卡在哪。**不要有第四轮**——超过三轮通常意味着问题不在代码，而在任务切分或设计。

**只有这五件事能停：**

| 能停 | 例子 |
|---|---|
| 不可逆或破坏性操作 | 删数据、改历史、重写别人正在用的东西 |
| 安全相关的动作 | 凭据、权限、对外暴露 |
| 工作区之外的副作用 | 推到共享分支、发版、动别人的环境 |
| 需要放松质量底线 | 只能靠改测试、改阈值、加抑制注释才过得去（见 `constraints`） |
| 计划烂到每条路都是猜 | 任务互相矛盾，或者设计文档根本没覆盖这种情况 |

其余一律**自己裁决、继续做**：在计划文件里按 `to-plan` 的裁决格式记一行，然后往下走。**一次错误裁决的代价是返工；一次卡住不动的代价是一整天，而且什么也换不来。**

## 收尾

所有任务都 `[x]`（或者有写明了原因的 `[!]`）之后：

1. 过 `verification`——没有本次实际跑出来的证据，不许声称完成。
2. 过 `code-review`——两个维度的评审。评审发现问题时，按 `code-review` 的接收流程逐条改；每改一条重新跑对应验证，改完再跑一次总验证。
3. **停在这里**，报告：
   - 碰了哪些文件
   - 计划里每个任务的最终状态
   - 设计文档的**每一条验收**逐条给结论：达成 / 部分 / 未达成 / 没验证
   - **你没能验证的东西**，单独一句说清楚
   - 用户接下来该提交什么

报告完就停。

## Red Flags

| 念头 | 现实 |
|---|---|
| 「计划里没写，但顺手改一下更好」 | 那是范围蔓延。要改，先回头改设计文档 |
| 「这任务太简单，验证跳过」 | 验证项是任务的一部分，不是可选项 |
| 「测试跑不了，应该差不多」 | 那是**没验证**。说成「通过」就是撒谎 |
| 「全做完了再统一跑一遍验证」 | 验证项在**每个任务结束时**跑，不是攒到最后 |
| 「上下文丢了，从头再跑一遍吧」 | 重读计划文件；遇到 `[~]` 先核对现有 diff 和记录，再从断点继续 |
| 「三轮回合过了，再试一次」 | 上限是硬的。停下报告 |
| 「这项目是 Spring Boot，所有任务都过一遍约定」 | 只对后端任务加载；文档、脚本、前端任务要的是别的东西 |
| 「多写点，以后可能用得上」 | 那是 `ponytail` 明令禁止的投机性构建；以后真需要时再加 |
| 「`ponytail` 说能砍，这个交付物就省了」 | 计划里的交付物不能砍；要砍范围，先回去改设计文档和计划 |
