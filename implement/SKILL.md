# 实施：逐任务推进

在一份**已经签过字**的实施计划上作业。

<HARD-GATE>
没有计划就停下来：调用 `to-plan` 生成一份并拿到签字。不许「边做边想」。
</HARD-GATE>

三条硬规矩：

1. **当前分支、当前会话。** 不新建 worktree，不另开会话，不派子代理替你做。
2. **不提交。** 提交是用户自己的事。你的「任务完成」判据里**不含提交**。
3. **进度记在计划文件里。**

## 循环

对计划里的每个任务，按顺序：

1. **读任务**：交付物、要碰的位置、覆盖哪些验收、验证什么。
2. **动之前先确认位置对得上**——改名了、挪走了、还要多碰一处，就先把任务里的位置就地更新，再动手。
3. **按 `tdd` 做**——仓库没有测试基建时走哪条路，它自己写了。
4. **跑这个任务的验证项**。跑不动（环境不允许）就把原因记下来，交给 `verification` 在收尾时显式标注，**不许当成通过**。
5. **就地更新计划文件**：任务从 `[ ]` 标 `[~]`，完成标 `[x]`；补一行「实际碰了哪儿、验证是怎么做的」。
6. **下一个任务。**

任务状态在计划文件里就地对改——不要攒到最后一起更新。

## 卡住的时候

**修复循环上限 3 轮。** 同一个任务连续三轮验证不过，停下来报告：现在什么状态、试过什么、你判断卡在哪。**不要有第四轮**——超过三轮通常意味着问题不在代码，而在任务切分或设计。

**只有这四件事能停：**

| 能停 | 例子 |
|---|---|
| 不可逆或破坏性操作 | 删数据、改历史、重写别人正在用的东西 |
| 安全相关的动作 | 凭据、权限、对外暴露 |
| 工作区之外的副作用 | 推到共享分支、发版、动别人的环境 |
| 计划烂到每条路都是猜 | 任务互相矛盾，或者设计文档根本没覆盖这种情况 |

其余一律**自己裁决、继续做**：在计划文件里记一行

```
裁决：<决定了什么> — <为什么> — <错了的话代价是什么>
```

然后往下走。**一次错误裁决的代价是返工；一次卡住不动的代价是一整天，而且什么也换不来。**

## 收尾

所有任务都 `[x]`（或者有写明了原因的 `[!]`）之后：

1. 过 `verification`——没有新鲜证据，不许声称完成。
2. 过 `code-review`——两轴评审。
3. **停在这里**，报告：
   - 碰了哪些文件
   - 计划里每个任务的最终状态
   - 设计文档的**每一条验收**逐条给结论：达成 / 部分 / 未达成 / 没验证
   - **你没能验证的东西**，单独一句说清楚
   - 用户接下来该提交什么

报告完就停。

## Red Flags

| 念头 | 现实 |
|---|---|
| 「计划里没写，但顺手改一下更好」 | 那是范围蔓延。要改，先回头改设计文档 |
| 「这任务太简单，验证跳过」 | 验证项是任务的一部分，不是可选项 |
| 「测试跑不了，应该差不多」 | 那是**没验证**。说成「通过」就是撒谎 |
| 「全做完了再统一跑一遍验证」 | 验证项在**每个任务结束时**跑，不是攒到最后 |
| 「上下文丢了，从头再跑一遍吧」 | 重读计划文件，从第一个不是 `[x]` 的任务接着做 |
| 「三轮回合过了，再试一次」 | 上限是硬的。停下报告 |
