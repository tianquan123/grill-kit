# 测试驱动开发

TDD 就是红 → 绿循环。本技能是让这个循环产出**值得留下的测试**的参考：什么算好测试、测试放在哪里、有哪些反模式、以及循环的规则。每一节在**每个循环**都适用：在循环之前和循环之中查阅，而不是事后再看。

探查代码库时，读 `CONTEXT.md`（如果存在），让测试命名和接口词汇与项目的领域语言一致，并尊重你触碰区域的 ADR。

## 什么算好测试

测试通过公开接口验证行为，而不是实现细节。代码可以整个换掉，测试不该跟着换。好测试读起来像一份规格说明："user can checkout with valid cart" 明确告诉你存在什么能力，而且它能在重构后存活，因为它不关心内部结构。

写第一个测试之前读 [tests.md](tests.md)（什么算好测试）；要用替身或打桩之前读 [mocking.md](mocking.md)。

## 接缝：测试放在哪里

**接缝（seam）**是你做测试的公开边界：在这个接口上你能观察行为，而不必伸手进去。测试住在接缝上，永远不针对内部实现。

**只在事先商定的接缝（模块之间可替换的边界）上写测试。** 在写任何测试之前，先把要测的接缝写下来。走 `use-grill` 的链时，接缝应在设计文档或计划里先写下来；计划没写就按当前档位自行裁决，有记录文件就记进去，局部档记在对话里的短设计里。单独使用本技能时，先跟用户确认再写。你不可能测所有东西，所以事先商定接缝，正是把测试精力投在关键路径和复杂逻辑上、而不是每个边界情况上的办法。

问："公开接口是什么，我们要测哪些接缝？"

当接口本身的形状还在讨论中（模块有多深、接缝该放哪里、接口该暴露什么）时，调用 Skill 工具加载 "codebase-design" 取词汇。它是模块（module）、接口（interface）、深度（depth）、接缝（seam）、适配器（adapter）、杠杆（leverage）、局部性（locality）这些术语的共享来源，是一份随时查阅的参考，不是一场要跑的会话。

## 反模式

- **与实现耦合**：mock 内部协作者、测试私有方法、或通过侧信道验证（绕过接口直接查数据库）。特征：重构时行为没变，测试却挂了。
- **同义反复**：断言用与实现相同的方式重算期望值（`expect(add(a, b)).toBe(a + b)`、手工用同样方式推出来的快照、把常量断言为它自己），于是它按构造就通过，永远不可能与代码产生分歧。期望值必须来自独立的事实来源：一个已知正确的字面量、一个手工算过的例子、或者规格说明。
- **横向切片**：先把测试全写完，再写全部实现。批量测试验证的是**想象中**的行为：你测的是东西的**形状**而不是面向用户的行为，测试对真实变化变得迟钝，而且你在还没理解实现之前就锁定了测试结构。改用**纵向切片**：一个测试 → 一个实现 → 重复，每个测试都是**曳光弹（tracer bullet）**，根据上一轮教会你的东西调整。

## 循环的规则

- **先红后绿。** 先写失败的测试，然后只写足够让它通过的最少代码。不要预判未来的测试，也不要加投机性的功能。
- **一次一个切片。** 每个循环：一个接缝、一个测试、一份最小的实现。
- **重构不属于这个循环。** 重构是独立任务，需要单独定档并取得批准（见 `use-grill`）；本技能只覆盖红 → 绿。

## 与 `ponytail` 的分工

两个技能并存的边界：**`ponytail` 决定验证写不写、写多大；本技能决定需要验证时怎么走（红 → 绿）。**

- `ponytail` 判据：平凡逻辑不需要测试（YAGNI 也适用于测试）；非平凡逻辑（分支、循环、解析、金额/安全路径）留**一个**可运行检查即可，测试数量以能表达意图的最小为准。
- 本技能判据：需要写验证时，先红后绿，一次一个切片，测试写在商定的接缝上；先看到失败再写实现，是红→绿的核心价值，不为有测试而多写。
- **免测 ≠ 没验证。** 不为一次平凡改动新增自动化测试，不等于交付时跳过验证——任务验证项与验收清单照走，交付前仍过 `verification`。

## 没有测试基建的时候

有些仓库里测试**跑不起来，或者根本不存在**（依赖拿不到、环境不在手上、这块从来没有测试）。这不等于可以跳过验证，只等于换一条路：

- **不要发明测试基建。** 给一个没有测试的项目第一次搭测试框架，是另一个任务，得单独定档，不能顺手做。
- **不要为了「有测试」而写一个跑不了、或者断言不了任何东西的测试。** 那比没有测试更糟：它会让 `verification` 误以为手里有证据。
- **换替代验证**：走 `verification` 里的降级路径——逐条对着验收清单静态核对、核对必须两处同步的定义、检查分层与命名约定、走查没处理到的路径。
- **如实标注**：报告里写明「这块没有自动化验证」，以及建议由谁、在什么环境里跑。

**红绿循环依然是纪律**，只是自动化不可用时：「看它失败」退化成「改动之前先确认问题确实存在」，「看它通过」退化成「改动之后按可观察的行为逐条核对」。
